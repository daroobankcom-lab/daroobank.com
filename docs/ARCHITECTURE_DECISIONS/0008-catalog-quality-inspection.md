# ADR 0008: bounded, read-only catalog quality inspection

Status: development-only implementation, 22 November 2026; extended by [ADR 0011](0011-indexed-irc-inspection.md). The original scan remains page-local.

## Decision

Offer an advisory inspection of existing `ProductPresentation` rows, separate from candidate ingestion and any future identity or approval workflow. The staff page `/staff/catalog/quality/` requires active staff with `catalog.view_productpresentation`, is behind the existing DEBUG-only portal gate and has private/no-store headers; it does not grant candidate permissions. A product-presentation-only user lands there after login. The separate management command `inspect_catalog_quality` is for trusted local operators and is not subject to the web authentication or DEBUG gate.

Each request reads at most 50 records plus one lookahead in ascending internal ID order and returns a next starting ID when more rows are observed. It flags unsafe/control text, inconsistency of the stored search and normalized IRC projections with their current source fields, source URLs failing the stricter internal URL policy, and published-flagged records rejected by the current shared public technical eligibility filters. The stricter URL warning is advisory: the existing public predicate allows some URLs it flags, such as query strings; this inspection does not change public behavior. Unsafe text makes eligibility unknown instead of trying to render or classify it. Exact normalized IRC duplicates are flagged only within the currently inspected batch, and only when each row's IRC projection is internally consistent. This includes drafts and does not establish identity. The report outputs internal IDs, status and fixed warning codes/labels, not names, source URLs, or other fields, and makes no writes or network requests.

## Limits

An absent warning is not a clinical, legal, source-rights, safety, identity, completeness or security approval. This is not reconciliation, an audit, a repair, or a publication/withdrawal mechanism. Published means a technical flag, and filter passage does not establish verified content. The page-local duplicate check misses matches in other batches and rows with inconsistent/invalid indexes. Browsing is forward-only, not a consistent database snapshot; concurrent changes, deletions or inserted lower IDs can be missed or appear differently between calls. Fifty-one rows are bounded, but row size, database work, query time and production load are not; this diagnostic is for synthetic local development, not a production monitoring service. It does not validate every model field, source or hidden write, and does not independently reconstruct source truth. Ordinary bulk/SQL writes can invalidate any findings immediately. No browser accessibility, production security, real source or clinical validation is implied.
