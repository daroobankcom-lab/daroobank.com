# ADR 0011: bounded cross-batch indexed IRC inspection

Status: development implementation, 22 November 2026; extends [ADR 0008](0008-catalog-quality-inspection.md).

The original quality scan still flags exact normalized IRC duplicates only among the 50 rows in its current batch. Add a separate read-only lookup anchored on one presentation ID: find other presentations anywhere in the catalog whose stored `irc_normalized` equals that anchor's recomputed, valid nonempty IRC. Check the anchor's original IRC and stored projection first; an empty or inconsistent anchor stops the lookup. At most 50 indexed candidates plus one lookahead are fetched per request in ID order; each candidate's original IRC and projection are rechecked, and inconsistent indexed rows are separately flagged rather than treated as matches. Results contain IDs and fixed statuses only, including unpublished records. No names, IRC values or URLs are deliberately rendered or output; no writes, external requests, identity decisions, repairs or publication occur.

The private staff route requires the existing `catalog.view_productpresentation` permission, active staff, DEBUG-only gate and privacy headers. The `inspect_catalog_irc` management command and service run outside the web gate for trusted local operators. A signed, one-hour forward cursor binds the anchor ID and keyed digest of its normalized IRC to the last inspected candidate ID. A changed or invalid anchor, altered/expired cursor, wrong anchor, key rotation or malformed token requires restarting. The token omits the raw IRC but includes IDs; signing is not encryption and the digest is not a confidentiality guarantee, especially with a known debug secret or guessable codes. URLs and tokens may appear in logs; use only synthetic data.

## Limits

This is an indexed clue lookup across the catalog, **not a complete global duplicate audit or uniqueness proof**. Incorrect or absent indexes can hide relevant rows; they are not found by this lookup. The separate sequential quality scan can flag index drift but is itself bounded and not a snapshot. The lookup does not assess names, strength, package, source, identity or medical equivalence. Candidate data and indexes can change between or during requests; inserts, deletion and updates can skip or alter results, and the anchor can change after it is read. An empty final page does not establish completeness. Row caps do not limit database scan/sort cost, elapsed time or load. Permissions, hashes and model guards do not establish rights or tamper-resistant audit. Production use still requires complete identity governance, database integrity checks, controlled repair, concurrency/security/load testing and clinical/legal review.
