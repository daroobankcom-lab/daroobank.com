# ADR 0014: Private ingredient, formulation and product correction branches

Status: development-only, 2026-11-22.

## Decision

Extend the existing private synthetic identity chain with three separate, typed immediate-parent correction links: `IngredientRevision`, `FormulationRevision` and `ProductRevision`. A correction creates a new assertion and link atomically; it does not edit the old record, rewire dependent records, copy reviews, select a preferred branch, establish equivalence, or publish anything. Existing records are not backfilled. Each link points to one parent and one child of the same type, has an author, reason, graph hashes and a payload hash; a child has at most one incoming link. The database enforces parent ID less than child ID and protects referenced records from ordinary deletion. Parallel branches are explicitly allowed.

For ingredient corrections, names and source metadata can change. A formulation correction preserves exactly the same ingredient IDs and ordering but may change name, source, dosage form, route and strength quantities/units. A product correction preserves the same formulation but may change product and source fields. At least one permitted value must change; a different composition or formulation must be entered as an independent assertion, not silently linked. These narrow rules do not certify clinical identity or scientific validity. Existing formulations, products and packages continue to reference their original records. New downstream assertions must be made explicitly when appropriate.

Active staff with `catalog.view_identityworkspace` and `catalog.add_identityworkspace` can create corrections in the development-only staff portal. CSRF, private headers and the synthetic-data assertion apply; direct services enforce permissions but not the web gate or checkbox. Forms show the prior graph and require a reason and expected graph hash. The formulation formset validates its fixed management shape and service independently checks ingredients and ordering. Within a PostgreSQL transaction, the service locks the immediate parent, rejects a changed/invalid graph, creates a validated child and link, and rolls back both on error. Formulation creation locks ingredients in ID order; product creation locks its formulation. Two cooperating corrections of one parent can create distinct valid branches. Non-package revisions do not have a review-history precondition because those record types have no reviews.

Detail pages display only internally consistent immediate links: link values/hash, parent/child graphs and type-specific dependency rules are checked. Inconsistent link details are hidden. Immediate children are scoped to the parent and paginated by descending link ID in blocks of ten; cursors are not access grants, and pages are not a snapshot. Only the immediate link is checked; no ancestor traversal, whole-history validation or inferred timeline is provided. Package revision behavior remains as described in [ADR 0013](0013-synthetic-package-revisions.md).

## Limits

The graph/link hashes are unkeyed and are not signatures, authenticity or durable audit. A privileged writer can bypass ordinary model guards through bulk operations/SQL, fabricate/recompute records, or race graph reads; the cooperative locks are not global isolation. A coherent link may still be wrong. Database constraints do not validate source rights, clinical content, same ingredient set or formulation identity; those are application checks. The endpoint can change claimed names, forms or units, and cannot ensure the correction describes the same real drug.

Existing package reviews cover only their package graph, not any correction link or earlier author. Authors of earlier versions are not automatically excluded from review of a later graph unless they also authored that graph. Correction provenance and ancestry require separate governance and review; do not treat these records as complete version governance, clinical approval, a reconciliation system or production audit. Only synthetic, nonconfidential data is allowed. Query plans and browser/accessibility, clinical, legal and production security validation remain unperformed.
