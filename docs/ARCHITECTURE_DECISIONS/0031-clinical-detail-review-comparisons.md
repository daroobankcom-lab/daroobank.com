# ADR 0031: distinguish clinical draft and reference comparisons in review detail

Status: development-only, 22 November 2026. The missing-draft-author limitation below describes the historical state; [ADR 0033](0033-missing-source-and-clinical-creators.md) narrows it. No review or draft records are rewritten; only synthetic data is appropriate.

## Problem and decision

The clinical detail previously compared the historical reference fingerprint to the present reference fingerprint but did not separately compare the reviewed draft to the currently observed draft. In particular, two empty reference lists can match even when a nonparticipating writer coherently changes the draft or changes its author ID. The detail also said references changed *after* review and called any snapshot without `evidence_version` old. Those conclusions do not follow from the comparisons or missing keys.

Reuse the existing review-inspection structural classifier for each of the at most 25 recent review rows on the private detail page. For a technically supported record, show a separate comparison of historical draft payload hash and snapshot author ID against the valid observed current draft. Separately compare historical and current reference-set fingerprints where both are available. When they differ, describe a difference without attributing a time or cause. When evidence keys are wholly absent from an otherwise supported record, say the evidence image is missing, not that the event is old. Unsupported/partial record shapes, invalid draft snapshot or invalid review metadata produce an invalid-record notice and hide decision/reason and historical references. Invalid reference images, including reviewer/contributor conflicts, do not display those references. If the current draft or immediate parent is inconsistent, comparisons are unknown and detail fields of the review are suppressed. If only current references are invalid or over limit, their comparison is unknown, but a structurally valid historical reference image may still be displayed.

The classifier checks bounded structural and fingerprint consistency, not proof of chronology or integrity. Review metadata, usernames and timestamps are not authenticated by the draft/reference hashes. Even a technically consistent review is not proof of actors' existence at an earlier time, qualifications, historical authorization or that the review actually occurred as described. The detail reads review rows without an inner reviewer join and looks up at most 25 distinct reviewer IDs in one separate query. A missing reviewer leaves the row and latest-review expectation visible but makes its detail/comparison unknown; it is not proof of when or why the account became unavailable. The separate review inspection also avoids that join but does not verify actor existence. The detail draft query still inner-joins its author, so a corrupted missing draft author can hide the draft. Current draft, evidence and reviews are fetched separately without snapshot isolation. A test changes the draft between reads, demonstrating a displayed match against the earlier in-memory draft even though the database has already changed; restoring an earlier value also yields a match (ABA). A matching hash is not proof there was no intermediate change. The review detail UI warns about separate reads and unknown change timing.

Tests exercise both comparison axes, same/different/unknown, author-only changes, supported missing evidence, partial shapes, contributor conflict, corrupted current evidence, invalid draft, non-snapshot/ABA, permission/privacy behavior, a missing reviewer under deferred FK corruption, the 25-row cap and no additional SQL query per displayed review in selected requests. The reviewer lookup adds one bounded query when reviews exist. Chromium checks the ordinary synthetic detail at four widths. Validation is repeated in Python for a technically consistent reference image, so bounded row count is not a performance benchmark or a bound on JSON bytes, database work or runtime. The 25-row detail cap is not a complete history, and no new access or write permissions, audit, source verification, clinical approval or production guarantee are added.
