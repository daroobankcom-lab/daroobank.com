# ADR 0036: current identity package reviewer lookup

Status: development-only, 22 November 2026. Extends the recent-review display approach of [ADR 0032](0032-reviewer-lookup-in-intake-history.md) to paginated identity package history and the latest-review display on package correction.

## Problem and decision

An identity package review's structural classifier validates the reviewer ID's shape and its independence from graph author IDs, but does not check if that account currently exists. With selected synthetic deferred-FK corruption, a structurally consistent review with a missing reviewer still exposed its decision, reason and claimed historical graph. Normal committed data with intact FK constraints should not have this corruption.

Package detail retains each review and keyset position but separately resolves at most 25 displayed reviewer IDs in one same-database lookup. The package correction page resolves the latest reviewer similarly. If an account is missing, show an unknown-details notice and suppress that review's decision, reason, date, reviewer ID and historical snapshot. The existing structural check remains independent: an invalid review with an existing reviewer remains hidden. The actual latest review ID continues to populate both forms and prevent stale submission. A structurally consistent prior review with a missing account does not itself block a new authorized review or package correction; an inconsistent latest review still blocks correction under existing rules. This is deliberate display behavior, not retrospective authentication, and no historical record is changed. Existing inactive/non-staff accounts count as present. Reads are separate, do not lock users and may be stale; present accounts are not evidence of historical identity or qualification.

The current identity graph and revision-link structural checks still validate recorded account **IDs** and hashes, not account existence, authority or authenticity. The identity workspace pages and lineage inspector explicitly state this; selected creation, review and revision services have not gained graph-creator existence checks. The same limitation applies to other unexamined relationships. A consistent graph, match, review or lineage result does not prove source rights, clinical equivalence or audit provenance.

## Evidence and limits

PostgreSQL tests temporarily corrupt reviewer FKs and restore them before the transaction ends; they cover latest and older-page reviews, hidden reasons, cursor/latest-version preservation, stale and fresh HTTP submissions, correction behavior, domain permissions and privacy headers. Additional tests cover inactive accounts, one account query per 25 reviews, and a same-transaction test-only mutation after lookup demonstrating stale display. A synthetic ingredient with a missing creator and recomputed hash is still structurally accepted and can be used in formulation creation; it is restored before test completion. Chromium covers normal identity views and warnings at four widths. These are selected bypass cases, not proof of deletion races or all schedules. Pagination limits output rather than query cost, bytes or runtime.

Review lookups, current graph reads and history reads do not form a single snapshot, and writers do not check prior reviewer existence. Later database mutations, ABA, other creators and direct SQL/bulk bypasses remain possible. No real data, authorization assurance, audit, production hardening, clinical approval or publication is implied.
