# ADR 0042: translate selected identity writer concurrency errors

Status: development-only, 23 November 2026. Applies only to selected private synthetic identity service transaction boundaries; it does not configure an operational timeout or automatic retry.

## Problem and decision

Identity graph locks can wait or produce PostgreSQL concurrency errors. Previously a selected lock timeout surfaced as an uncaught database exception, including from private HTTP operations. After permissions and input checks, formulation/product/package creation, ingredient/formulation/product/package correction, and package review now run their existing atomic blocks through a small boundary. Once that block or savepoint has rolled back, PostgreSQL SQLSTATE `55P03` (lock not available, including lock timeout), `40P01` (deadlock detected), and `40001` (serialization failure) are translated to an `IdentityConflict` with a generic message. The existing private HTTP paths map this to 409. The original exception is chained for server-side diagnostics, not displayed as user text.

No timeout, isolation level, retry, connection recovery, or global exception handler is introduced. Unrecognized database errors, including `57014` query cancellation, are re-raised. Simple ingredient creation and unrelated services remain outside the boundary. A failure at the commit of an enclosing transaction **after** a nested service returns is outside the boundary. Callers using an outer transaction must handle such errors themselves, and a serialization failure or deadlock requires abandoning/retrying the whole enclosing transaction as appropriate; catching `IdentityConflict` does not make an outer transaction's prior reads safe. A lock timeout inside a savepoint can be rolled back without poisoning the enclosing transaction in the selected test, but that is not a general transaction-retry guarantee.

## Evidence and limits

Synthetic separate-connection PostgreSQL tests force real lock timeouts in eight selected service and HTTP cases; verify rollback, private 409 headers and no raw DB message; and exercise a nested savepoint timeout. A coordinated real deadlock identifies the selected victim's `40P01` and verifies no second review. A real serializable transaction receives `40001` inside the service boundary; the test rolls back the entire outer transaction. Additional injected SQLSTATE tests cover all three mappings and rollback, plus rethrowing unrelated errors. Test timing, victim selection and all production deployments are not proven by these schedules. No indefinite-wait bound, performance or deadlock-freedom claim follows. Existing phantom inserts, same-transaction bypasses, later writes, account races, and partial graph/history coverage remain. Neither a conflict nor a retry establishes historical identity, rights, provenance, clinical safety or production readiness.
