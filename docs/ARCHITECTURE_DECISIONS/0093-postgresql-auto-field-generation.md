# ADR 0093: PostgreSQL auto-field generation clues

Status: development-only implementation, 24 November 2026; extends [ADR 0070](0070-postgresql-catalog-clues.md) and [ADR 0092](0092-postgresql-migration-recorder-primary-key.md). [ADR 0094](0094-postgresql-serial-default-clue.md) adds a selected legacy-default comparison, superseding that limitation below.

## Decision

The inspector derives standard Django `AutoField`, `BigAutoField` and `SmallAutoField` columns from current managed models, implicit many-to-many models and the migration recorder. For each, it looks for a PostgreSQL owned sequence and either `GENERATED BY DEFAULT AS IDENTITY` or a non-identity column with some database default, allowing legacy serial-style tables. Missing selected generation clues, identity `ALWAYS`, or unsupported custom auto-field subclasses produce aggregate `attention`. The catalog inspection remains one read-only statement with no object names or repair.

This deliberately limited clue does **not** verify that a legacy default actually calls the owned sequence, that the sequence's value is ahead of table data, sequence privileges, increments, bounds, cache, historical migration intent or every generated column. A constant default can pass if an owned sequence is also present; an alternate valid configuration can be flagged. Clean findings do not certify insert behavior, backup recovery or production readiness. The opt-in synthetic restore drill separately tests selected post-restore writes and one rewound sequence, not every sequence.

## Evidence

In a synthetic PostgreSQL 16 database, rolled-back DDL removes identity generation on ordinary, auto-created many-to-many and migration-recorder tables, changes identity to `ALWAYS`, and tests serial-style sequences with missing ownership or default. These cases are flagged. A legacy-style owned sequence with a default passes; a deliberately wrong constant default also passes, recording a blind spot. Unsupported metadata and a custom subclass are counted, and the full command is exercised in a read-only transaction. No production repair or migration is implied.
