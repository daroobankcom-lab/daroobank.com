# ADR 0135: selected staff form error summaries

Status: development-only accessibility improvement, 24 November 2026. Follows ADRs 0133–0134.

Validation errors were already shown next to individual fields and Django associated visible fields with their errors, but selected long forms had no top-level cue that submission failed. The source-claim create, clinical create/revision and reference, identity create (including its component formset), and product/price upload pages now prefix the document title on invalid submissions and show a linked error summary before the form. Links use the actual field IDs, including formset prefixes. Hidden-field and general or formset-structure errors get generic guidance rather than links to invisible controls. Individual detailed errors remain in their existing locations. Initial GETs and successful submissions do not show the summary. No submitted values are included in the summary; this does not prevent their display elsewhere or logging.

The summary is server-rendered and requires no script or automatic focus. A keyboard user can navigate to a summary link and activate it to reach a selected invalid field; support for other browsers, screen readers, announcements, all error types or all staff forms is not established. An initial Chromium run exposed a retained error-field fragment on the redirect after resubmission; the selected forms now explicitly submit to the server path and query (the fragment is client-only). The subsequent synthetic Chromium run passed the selected keyboard, redirect, layout and axe checks; inconclusive contrast results still require manual review. Error recovery still requires manual re-entry of file inputs. This is not a comprehensive accessibility or security assessment.

Synthetic HTTP tests cover selected field, hidden, general and component-formset errors, normal GET and no write on selected invalid POSTs. A synthetic Chromium test checks the title, the existing field/error association and keyboard activation of one summary link, with an axe scan of that invalid identity page. Other pages, devices, browser/assistive-technology combinations and manual contrast remain to be reviewed.
