# ADR 0137: selected price-review snapshot consistency clues

Status: development-only defensive display, 24 November 2026. Extends ADRs 0065 and 0128 without changing review writes.

The private price detail showed a reason and an accepted-product image for each recent review whenever the reviewer account was currently found, without validating the stored review or snapshot. A malformed or partially changed snapshot could therefore be presented as an ordinary historical review. It is not evidence that a real event occurred.

For the same at-most-25 recent review rows already read by the detail view, a pure classifier now checks the selected review ID relationships, decision, reason, historical author and rights assertion; exact snapshot shape; validated source metadata and price CSV fields; amount conversion and candidate digest; and, for acceptance, the product-image shape, ID, bounded identity fields, normalized match and product-image digest. Rejections and deferrals must not contain a reviewed product or product hash. The page replaces the reason and image of an invalid record with a fixed warning. If the reviewer account is missing, the existing generic missing-account display still takes precedence. Valid snapshots are compared with the current candidate and labeled same, different or unknown; only the candidate is compared, not the present product. An unavailable/inconsistent current candidate or missing current stager yields unknown. GET and invalid/stale review POSTs use the same display path.

This is a consistency clue, not proof of authorship, source rights, price validity, product identity, review time or historical truth. Digests are unkeyed; the price candidate hash does not include source URL. A coherent rewrite and recomputed hashes can pass, and selected changes to a valid source URL can pass the historical check. The current snapshot comparison can identify an exact difference, not its cause or time. Candidate, review and account reads are separate, so an in-flight page is not a snapshot. This does not validate all history, prevent edits, change write-side locks or review eligibility, repair data, establish actor identity, or suppress metadata/context/logs elsewhere. Fetching at most 25 reviews does not bound database work or the sizes of their JSON/text columns; direct SQL and bulk writes remain outside the application protections.

Synthetic PostgreSQL tests cover genuine accepted, deferred and rejected events, selected malformed snapshot/amount/actor/product cases, hidden untrusted values on detail and error responses, same/different/unknown comparisons, bounded classification, no classifier queries and a coherent rewrite that still passes. A Chromium fixture bypass-writes one invalid review and checks the warning and absence of selected canaries alongside a valid review. These are selected examples, not exhaustive audit, Unicode, concurrency, accessibility or production security tests.
