# ADR 0140: selected product-review snapshot consistency clues

Status: development-only defensive display. Extends the price-history pattern in ADR 0137 to the product-candidate detail page without changing writes.

Previously this private page displayed a review reason when a reviewer account currently existed, even if the historical snapshot was malformed or no longer matched its stored digest. The page now classifies the at-most-25 recent review rows already fetched. A pure classifier checks selected ID relationships, decision and reason, the historical stager and rights assertion, exact snapshot shape, source metadata, candidate fields and the unkeyed product-candidate digest. It does not query accounts. Inconsistent records show a fixed warning instead of their reason; a missing reviewer retains the existing generic missing-account display. Valid snapshots receive same/different/unknown comparison against selected current candidate fields, only when the current candidate is consistent and its stager account is found. GET and invalid/stale review POSTs share this display. The writer's latest-review conflict check is unchanged.

This is not proof of authorship, source rights, product identity, history or time. A coherent rewrite with a recomputed digest can pass. Comparisons describe current in-memory values, not why or when they changed; candidate, review and account reads are separate, and a page is not a database snapshot. Account existence is not evidence of historical identity or permission. This feature does not cover every history row or other private views, logs, metadata or template context; it does not prevent writes, validate all historic versions, change review authorization, or repair records. The 25-row limit bounds classifier calls, not database work or the size of fetched JSON/text. Direct SQL and bulk writes bypass application guards.

Synthetic tests cover real writer decisions, malformed shapes and metadata, selected actor/digest faults, invalid GET/400/409 suppression, missing current stager, same/different/unknown states, bounded calls, classifier no-query behavior and a coherent rewrite that still passes. A Chromium fixture bypass-mutates one synthetic history row, checks the warning and absence of selected canaries alongside a valid row, and checks selected layouts and automated accessibility. These checks are not exhaustive Unicode, concurrency, accessibility or security validation.
