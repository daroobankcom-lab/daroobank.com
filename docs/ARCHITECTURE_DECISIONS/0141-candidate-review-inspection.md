# ADR 0141: bounded product and price review inspections

Status: development-only, synthetic data. Builds on the selected detail-display checks in ADRs 0137 and 0140; it changes no review writes.

The candidate detail pages show at most 25 recent review records. To let authorized staff inspect older selected history without displaying review reasons or snapshots, each candidate now has a read-only inspection page. It requires the corresponding candidate view permission and an active staff account, as does its direct service. It reads one candidate and at most 51 ascending review rows scoped to that candidate after a validated positive-or-zero bigint cursor; at most 50 are classified and the extra row is only a continuation sentinel. Category filtering occurs *after* selecting the batch. Even an empty filtered batch can offer the next cursor. The cursor is an internal ID, not a signed snapshot token.

Only fixed status/comparison labels, review IDs, counts and navigation are rendered. Existing product/price classifiers check selected snapshot consistency. The current candidate's consistency and the existence of its current stager account determine whether comparison is available; no reviewer account is fetched or validated. Actor permissions are checked before viewing, but this is not historical identity, authorization, provenance, source rights, a price endorsement or a complete audit. Hashes are unkeyed and coherent rewrites can pass. Reads are separate and concurrent changes can yield stale comparisons, gaps or repeats; deletion, insertion and bypass writers remain outside guarantees. IDs at or below zero are not scanned. The 51-row fetch bounds row count, not bytes in JSON/text or PostgreSQL execution and storage work. Error responses use a fixed restart link and do not echo invalid query values. HTTP GET/HEAD only, with existing private/no-store middleware and no writes.

Synthetic tests cover direct and group permissions, separate domains/candidates, input boundaries and localized digits, no-echo invalid inputs, no writes, selected fixed-size SQL, filter-after-scan continuation, empty batches, missing stager, malformed records and a deliberate stale-parent observation. Chromium tests cover both pages at four widths, localized input, keyboard navigation, fixed error recovery and selected axe checks; manual contrast and comprehensive assistive-technology testing remain outstanding. This is not a production deployment decision.
