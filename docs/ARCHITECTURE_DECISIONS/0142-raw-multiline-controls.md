# ADR 0142: selected raw multiline text controls

Status: development-only form validation. Extends ADR 0133 to selected multiline fields without changing the allowed multiline policy.

Django's `CharField` strips boundary whitespace before the service receives it. Some forbidden Unicode control characters, such as U+001C and U+0085, can be stripped silently, while other disallowed characters could reach a service and produce only a general conflict. A user could therefore submit a value different from the one recorded without an explicit field error.

For review reasons in product, price, source, clinical and identity package forms; clinical draft statements and revision reasons; and the four identity revision reasons, a shared form mixin checks the selected raw widget value before accepting cleaned data. It rejects Unicode Cc controls other than tab, carriage return and line feed, and rejects surrogate characters. The field gets a fixed error and is removed from cleaned data. Ordinary whitespace is still trimmed by Django; multiline tab/newline/carriage-return and Persian ZWNJ remain allowed. A shared predicate also expresses the existing service-side clinical statement and review-reason character policy; it does not change the service length, trimming or permission rules.

Selected synthetic form tests cover prefixed forms and start/middle/end controls, allowed multiline text, shared-policy equivalence and invalid cleaned-data removal. CSRF-authorized HTTP tests cover the five review endpoints plus clinical create/revision and ingredient revision, checking rejection without writes and a valid follow-up. Selected Chromium product and price review checks submit U+001C and confirm the field error. This is not a comprehensive Unicode spoofing, transport, browser, log, storage or accessibility guarantee. The bound form may still redisplay submitted values, and other forms, services, imports, direct database writes and logs are outside this raw-form guarantee. No production data was used.
