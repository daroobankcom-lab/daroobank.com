# ADR 0144: identity revision error navigation

Status: development-only, synthetic data. Builds on the selected form summaries in ADR 0135 and review summaries in ADR 0143; no revision writer, permission, transaction or validation rule changes.

The ingredient, formulation, product and package correction forms previously rendered field errors without a page-title indication or top-of-form navigation. When the form is actually available, these pages now reuse the existing server-rendered error title and summary. Visible form and formulation component errors link to their field IDs; hidden-field errors and formset management errors use general recovery guidance, without copying submitted values into the summary. A stale conflict still hides the form and directs the user to reload; the document title indicates the failure but no links point at absent fields. When the graph or latest package review is invalid and the form is unavailable, the existing disabled-state message remains instead of exposing links to missing controls. This does not alter which HTTP responses or writes occur.

Synthetic HTTP tests cover four revision types, hidden and visible errors, CSRF, selected formset errors and malformed management input, unavailable graphs and invalid latest review, 409 conflicts, no writes and corrected follow-up submissions. Chromium exercises keyboard navigation and selected automated accessibility checks for an ingredient reason and a formulation component at 390 CSS pixels. These checks do not establish comprehensive accessibility, screen-reader support or security; selected contrast checks still need manual review. Bound forms can redisplay inputs outside the summary. This is not a production deployment decision.
