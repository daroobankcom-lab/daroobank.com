# ADR 0145: offline window form input and errors

Status: development-only, synthetic testing. The private window page remains an offline calculation, not a scheduler, authorization, source-rights check or dispatch mechanism.

The form previously let Django strip boundary control characters before time and timezone validation, and only validated time syntax when both fields were present. It also presented errors without the existing top-level navigation or an error-specific title. The three raw single-line widget values now reject Unicode Cc and surrogate characters before accepting cleaned values. Ordinary surrounding spaces remain trimmed. Each time and zone is validated independently and gets its own field error; equal times remain a general error. DST ambiguity and other planning failures remain general errors. Existing service parsing, time calculations, authorization, methods and statuses are unchanged.

The shared error summary links to visible fields and uses generic guidance for non-field errors without repeating input. A default-plan failure on an unbound page continues to be displayed separately. Synthetic tests cover selected raw controls and prefixed inputs, independent invalid fields, equal times, a DST fold, no calculation on invalid input and private headers; Chromium exercises one error link with keyboard navigation and a corrected GET at 390 pixels. Bound values can still appear in the form and URL; this is not comprehensive Unicode, privacy, timezone database, accessibility or security assurance. Selected contrast checks require manual review. No production data was used.
