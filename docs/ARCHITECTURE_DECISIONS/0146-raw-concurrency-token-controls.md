# ADR 0146: selected raw concurrency-token controls

Status: development-only form validation with synthetic tests. No service, database schema or locking change.

Some hidden optimistic-concurrency inputs were silently changed by Django field cleanup: for example, a boundary control could be trimmed from a hash or integer, or an optional price-match hash consisting only of a control could become empty. A CSRF-authorized request could then reach a writer with a token different from the submitted string. The selected product, price, source, clinical and identity review forms, clinical revision/reference forms, and identity revision forms now also inspect their raw hidden concurrency-token widget values through the existing single-line control mixin. Unicode Cc and surrogate characters produce a field error and remove that field from cleaned data. Existing other syntax and length rules remain in force; some identity RegexFields already reject surrounding spaces, whereas other fields retain their previous trimming. This is not a signature, anti-tampering mechanism, authentication of the caller, or an improvement to the underlying lock/snapshot guarantees.

Prefixed synthetic form tests cover selected controls at both ends of each named token, optional empty hash, ordinary whitespace behavior and removal from cleaned data. CSRF-authorized HTTP tests exercise all five review endpoints, clinical revision/reference, identity ingredient and package revision, no write after invalid input and selected clean follow-up submissions. The existing generic hidden-field recovery summary is retained; a bound form may still redisplay raw submitted values elsewhere. Other fields, alternate writers, Unicode format characters, logging and transport remain outside this guarantee. No production data was used.
