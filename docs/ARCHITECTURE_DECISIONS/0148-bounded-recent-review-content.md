# ADR 0148: bound selected recent-review content transfers

Status: development-only defensive display with synthetic tests. Extends ADRs 0031, 0032 and 0147; it does not change review writes, permissions, optimistic tokens, retention or authorization.

## Decision

Four private detail pages (product candidate, price candidate, source claim and clinical draft) previously limited recent review rows to 25 but selected each review's entire JSON snapshot and reason. The shared scoped history reader now limits selected JSON by its PostgreSQL textual representation to 65,536 characters and returns at most the first 1,001 reason characters. These thresholds are shared with the candidate review scan. Its SQL defers the original columns, evaluates length and conditional JSON in the same SELECT, and replaces deferred attributes to prevent later lazy fetches. A row over either bound is labeled `oversized`; both model attributes are set to `None` and its review detail, assertions and comparison are not classified or displayed. Fixed explanatory text states that the content was not examined and comparison is unknown. The row remains in the newest 25 and its ID remains the expected-review token, including when its reviewer account is missing. No write is made by this handling. Smaller malformed JSON remains subject to the existing fail-closed classifiers.

The unchanged separate account lookup does not prove historical identity. `oversized` takes precedence over missing reviewer and unavailable current parent for that row. At this decision, source and clinical scan pages were separate and did not acquire this protection; ADR 0149 subsequently added selected bounds to those scans. Parent records, other columns and pages, direct SQL, storage and write services remain outside the boundary. The bound counts characters in PostgreSQL's textual JSON representation, not exact wire bytes; up to 25 near-limit values can still be transferred. Casting and length operations can require full database decompression and substantial CPU, memory or time. It is not a production resource budget, content authenticity, clinical validity, audit or privacy guarantee, or proof of historical completeness.

## Evidence

Synthetic PostgreSQL tests exercise all four domains, very large JSON and reason-only records, exact character limits, malformed small JSON including JSON null, newest version ID, missing reviewer, GET and invalid POST, valid neighboring records, SQL shape, two-query lookup, absence of reflection and no history mutation. Existing classifiers and review workflows are regression tested. Synthetic Chromium checks the new product and price labels and non-disclosure at four selected widths; source and clinical oversized states are covered by HTTP tests, not browser corruption. Accessibility checks cannot certify accessibility and some axe contrast results still need manual review.
