# ADR 0205: identifier-shape and method parity on staff object routes

Status: **development-only synthetic evidence**, not an authorization review or an approval. The `API and permissions` release gate remains open.

## Context

ADR 0204 compares the denial for an existing row with the denial for one missing primary key. Two further channels were unmeasured: the *shape* of the identifier (zero, negative, oversized, non-numeric, an Arabic-Indic digit, surrounding whitespace) and the *HTTP method*. A route that answers a malformed identifier differently from a well-formed forbidden one, or that answers a wrong method differently per account, tells a probing client something even when every status code stays a denial.

## Decision

Add `daroobank/test_staff_identifier_parity.py`, which probes all 23 staff object routes with thirteen invalid identifiers and both method directions across five account shapes (anonymous, active non-staff, staff without permissions, staff with view permissions, staff with every permission), reusing the ADR 0201 row fixtures. Recorded behavior:

**Group A — identifiers the `<int:pk>` converter accepts** (`999999999`, `0`, a 20-digit value, `9223372036854775807`, plus the existing key):

* an unauthorized shape receives **one identical 403** for all five, existing row included — status, body bytes and headers;
* an authorized shape receives **one identical 404** for all four invalid ones, so absence is indistinguishable from out-of-range.

**Group B — identifiers the converter rejects** (`-1`, `abc`, `1.5`, `1%2f..`, empty, `' 1'`, `'1 '`, `'+1'`, `١`): no route matches, so **every shape, anonymous included, receives the identical unmatched-URL 404** rather than a 403, carrying the staff privacy headers (`no-store`, `noindex, nofollow`, `same-origin`). Recorded as a finding: a malformed identifier is answered differently from a well-formed but forbidden one. That reveals URL grammar, is generated by Django's dispatcher before any view runs, is the same for every account, and says nothing about whether a row exists.

**Method groups**, pinned at 14 / 5 / 4:

| Group | Wrong-method answer |
| --- | --- |
| safe-only (14) | 405, empty body, `Allow: GET, HEAD`, identical for all four authenticated accounts — answered *before* authorization |
| POST-only review routes (5) | 405 on a GET, identical for all four authenticated accounts, also before authorization |
| `require_http_methods(['GET', 'POST'])` form routes (4) | the method is not a gate: unauthorized accounts get the usual identical 403, an authorized account gets the form re-rendered (200) for its empty POST |

An anonymous request is redirected to the staff login in every group. Probing all thirteen identifiers plus the wrong-method request against existing rows, with all five shapes, leaves the fourteen write and audit model counts unchanged.

A red check confirmed detection: reordering `ingestion/staff_views.py::receipt_detail` so the identifier range check ran before the permission check failed two group-A assertions before the change was reverted.

## Limits and consequences

- **The 405-before-authorization answer is a small information leak that this suite records rather than removes.** It discloses which methods a route accepts to any authenticated account, including one with no permissions. It does not disclose row existence, and changing the order would require touching every view decorator for no measured gain.
- Group B parity is asserted per route, but the response comes from Django's URL dispatcher, so it demonstrates nothing about the views behind those routes.
- Thirteen identifiers are a sample, not an exhaustive grammar. Percent-encoded path traversal beyond `1%2f..`, very long identifiers, NUL bytes, and identifiers that differ only after Unicode normalization are not probed; the Arabic-Indic digit case tests the converter, not normalization.
- The dual-method routes are POSTed an empty body, so a valid submission is not exercised here; the revise and reference suites cover those paths, including their actor rechecks.
- Timing is not compared, for the reason given in ADR 0204: wall-clock differences inside a test process measure the harness.
- Headers are compared as the test client renders them; a reverse proxy downstream can add, remove or reorder them.
- Synthetic data on a development-only portal. No production readiness, threat model, independent review or real-data permission follows.

## Selected evidence

`daroobank/test_staff_identifier_parity.py` (6 tests) passes on synthetic PostgreSQL in normal and optimized mode, as part of a 41-test group with the ADR 0200–0204 suites.
