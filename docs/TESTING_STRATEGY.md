# Testing strategy and performance budgets

The development slice has Django tests; see [changelog](CHANGELOG.md) for actual runs. No browser-based performance benchmark has been run. Targets below are provisional acceptance budgets, not observed performance or promises; revisit with representative Iranian traffic, hosting and device/network conditions.

## Quality gates

- **Unit/property tests:** Unicode ي/ی, ك/ک, Persian/Arabic/ASCII digits, half-space, mixed RTL/LTR; identity ambiguity, currency and exact Toman-to-Rial conversion, decimal edge cases, effective dates and price percentages including zero/missing prior value.
- **Integration/database:** foreign keys, duplicate source revision, idempotent retries, append-only history, concurrent approvals, atomic publication/rollback, backdated corrections, cache invalidation, migrations and backup restore.
- **API/security:** contract schemas, pagination stability, malicious input, rate limiting, CSRF, authentication, MFA, object authorization, reviewer separation, no drafts/raw/PHI leakage and role escalation. Dependency scans and secret scanning.
- **Frontend:** mobile RTL and mixed-direction, keyboard and screen-reader flows, WCAG 2.2 AA target, contrast, real-device usability and low-JS fallback; patient versus professional views, explicit sources, stale/unknown prices, noindex and canonical tags.
- **Ingestion:** permitted sanitized fixtures for pagination and format drift, empty/partial responses, checkpoint recovery, HTTP timeouts, rate limiting, duplicate/missing IDs, maker/strength/form/pack mismatches, anomalies, source conflict and replay. Verify failed or partial runs never supersede verified data or mark missing products discontinued. Include timezone and 23:00→01:00 cross-midnight tests.
- **Clinical:** independent reviewer checks claims, references, scope, translations and correction/withdrawal; licensed interaction dataset coverage distinguishes verified negative vs not assessed. No safety-critical tool release without independent clinical validation.

## Opt-in synthetic search index experiment

`DAROOBANK_SEARCH_BENCHMARK=1 python manage.py test catalog.test_synthetic_search_benchmark --settings=daroobank.synthetic_test_settings --noinput` compares existing search with test-only GIN trigram and partial B-tree ordering indexes over 100,000 fictional records. It requires `pg_trgm` to be available and creatable in an authorized disposable PostgreSQL cluster; never run it on production. It builds and updates many test rows, creates an extension and two indexes in the randomly named test database, removes its own GIN index for one comparison, and attempts cleanup; interruption can leave resources requiring identity-verified manual handling. Its selected warm in-process samples include four concurrent clients for one repeated query; there is no performance threshold. No app migration adds the index. A local observation and important limitations are documented in [ADR 0120](ARCHITECTURE_DECISIONS/0120-synthetic-search-index-experiment.md).

## Measurable target proposal

On a defined low-end Android test device with throttled 4G and warm cache: p75 LCP <2.5 s, CLS <0.1 and INP <200 ms for indexable pages; target initial compressed JS <50 KB for public content pages, with an explicit exception process for complex tools. On a staging dataset of 100,000 synthetic packages with representative Persian variants and recorded concurrency, target server-side search p95 <300 ms and p99 <1 s, error rate <1%; measure DB plans, cache status, CPU and dataset size. Verify crawler at maximum configured concurrency does not increase public search p95 by >20% relative to identical baseline, on documented resources. These are experimental budgets, not achieved results. Run Lighthouse/WebPageTest-style controlled browser tests and load tests, recording tool versions, hardware, sample size, dataset and network. Do not use production PHI.

## Release criteria

All relevant tests pass in CI and staging; no critical unresolved security issues; editorial/source approvals and backup restoration signed off; performance measured against agreed targets. Test failures block release. Accessibility and Persian search failures receive explicit triage rather than silent waivers.

## Isolated general PostgreSQL tests

`daroobank.synthetic_test_settings` selects a fresh random test database name and the guarded runner that rejects reuse and Django parallel mode. `daroobank/test_synthetic_restore_guard.py` checks name generation, base-settings isolation and flag rejection, including parsed abbreviations. ## PostgreSQL catalog inspection

`daroobank/test_postgresql_inspection.py` uses a disposable PostgreSQL database to create a real unvalidated constraint, disabled trigger and invalid index after a failed concurrent build, plus missing and non-table relations and missing or wrong-target foreign keys; it verifies fixed aggregate output, nonzero anomaly exit, cleanup, DEBUG gate and generic errors. Further rolled-back tests cover an unexpected non-deferred FK, duplicate immediate or cascading FKs, missing unique/primary keys, partial indexes, reordered keys, nondefault null semantics for selected unique keys and missing or wrong-type named model checks; a same-named wrong check expression intentionally goes undetected. The null-semantics test uses PostgreSQL 16; see [ADR 0085](ARCHITECTURE_DECISIONS/0085-postgresql-unique-null-semantics.md). Tests also add unsupported unique declarations to model metadata and verify aggregate attention and a single read-only catalog statement; see [ADR 0086](ARCHITECTURE_DECISIONS/0086-unsupported-unique-declarations.md). Deferrable constraints in either initial mode are flagged, while a standalone immediate unique index still matches; see [ADR 0087](ARCHITECTURE_DECISIONS/0087-postgresql-unique-enforcement.md). Nondefault operator classes and index-versus-column collation differences on either key of a composite unique index are flagged; see [ADR 0088](ARCHITECTURE_DECISIONS/0088-postgresql-unique-operator-collation.md). See also [ADR 0074](ARCHITECTURE_DECISIONS/0074-postgresql-check-constraint-names.md). See [ADR 0072](ARCHITECTURE_DECISIONS/0072-postgresql-foreign-key-behavior.md) and [ADR 0073](ARCHITECTURE_DECISIONS/0073-postgresql-unique-key-clues.md). Missing managed columns, nullability differences and selected varchar, numeric and timestamp type changes are tested with rolled-back DDL. Unsupported types are reported, while auto-created many-to-many and migration-recorder primary-key types are intentionally skipped and counted separately. Rolled-back DDL also covers recorder column presence, nullability, selected types and primary-key presence, but not its row contents or current sequence value; see [ADR 0075](ARCHITECTURE_DECISIONS/0075-postgresql-column-clues.md), [ADR 0078](ARCHITECTURE_DECISIONS/0078-postgresql-column-type-clues.md), [ADR 0089](ARCHITECTURE_DECISIONS/0089-postgresql-migration-recorder-columns.md) and [ADR 0092](ARCHITECTURE_DECISIONS/0092-postgresql-migration-recorder-primary-key.md). Additional index DDL tests cover missing field indexes, partial/hash replacements, a longer B-tree prefix and named-index mismatches in sort direction, default null ordering, nondefault operator class, index-versus-column collation and included columns; a storage-option change intentionally goes undetected and unsupported metadata produces attention. See [ADR 0080](ARCHITECTURE_DECISIONS/0080-postgresql-index-presence.md) through [ADR 0084](ARCHITECTURE_DECISIONS/0084-postgresql-index-collation-and-include.md). Auto-field DDL tests cover missing and always identity, missing sequence ownership/default, a canonical legacy serial case, wrong defaults and a shadowed function; an equivalent noncanonical expression is conservatively flagged, and unsupported custom fields cause attention. See [ADR 0093](ARCHITECTURE_DECISIONS/0093-postgresql-auto-field-generation.md) and [ADR 0094](ARCHITECTURE_DECISIONS/0094-postgresql-serial-default-clue.md). An out-of-scope defect intentionally goes undetected. CI runs the read-only command after migration. These selected catalog states do not establish schema equivalence, data integrity, full corruption detection, security or production readiness; see [ADR 0070](ARCHITECTURE_DECISIONS/0070-postgresql-catalog-clues.md).
